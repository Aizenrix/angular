## Обязательные требования

- [x] Маршруты `/`, `/site/:id`, `/about` и `*`. Меню использует `NavLink`.
- [x] Сводка считает неработающие сайты, карточки показывают статус последней проверки и ведут к истории.
- [x] На странице сайта видны его адрес, число успешных проверок и таблица с выделенными сбоями. Для неизвестного ID есть сообщение и ссылка на главную.
- [x] Общий провайдер загружает `sites.json` и `results.json`. Шапка и страницы читают данные через `useMonitoring`. Есть индикатор загрузки и сообщение с HTTP-кодом при ошибке ответа.
- [x] Сайт опубликован на GitHub Pages. Прямая ссылка открывается в новой вкладке и после перезагрузки. Pages возвращает приложение из `404.html`.
- [x] Проверка настроена на 00:00 МСК. Ручные прогоны записали историю коммитами бота и заново опубликовали сайт.
- [x] Ночное сообщение приходит только при новом сбое или восстановлении. Токен и номер чата хранятся в GitHub Actions Secrets.
- [x] `npm run build`, `npm run lint` и `npm test` проходят.
- [x] В `sites.json` пять публичных сайтов GitHub Pages с уникальными латинскими ID. В методичке предусмотрены сайты однокурсников, для этого варианта по просьбе автора выбраны публичные проекты.

## Дополнительные задания

- Доля успешных проверок на карточке и фильтр «Только неработающие».
- Полосы времени ответа и HTML-заголовок на странице сайта.
- Понедельничная сводка за последние семь проверок в Telegram. [Контрольный запуск](https://github.com/Aizenrix/monitoring1/actions/runs/44690869724).
- Оценки скорости и доступности интерфейса от Lighthouse по шкале 0–100. [Контрольный запуск](https://github.com/Aizenrix/monitoring1/actions/runs/44691844037).

# Заявки в общежитие

Доска заявок жильцов общежития на React, TypeScript и Vite.

## Что сделано

- В обязательной части есть форма, пять стартовых заявок, карточки со статусами, фильтрация, сохранение в браузере и доставка уведомлений через n8n.
- В дополнительных заданиях реализованы счётчики фильтра, возврат заявки, поиск, отметка срочности и статус в Telegram.

## Запуск и проверка

Требуется Node.js 20.19+ (ветка 20) или 22.12+.

```bash
npm ci
npm run dev
```

Откройте http://localhost:5173. В новой сессии видны пять заявок, из них три новых.

## Запуск n8n и подключение Telegram

Запустите Docker Desktop. В подкаталоге `avtomatizaciya` выполните:

```bash
docker compose up -d
docker compose ps
```

На компьютере, где проводилась проверка, workflow уже опубликован, а настройки бота хранятся в томе Docker `n8n_data`. Следующие шаги нужны при развёртывании на другом компьютере или настройке другого бота.

1. Откройте http://localhost:5678 и при первом входе создайте локального владельца n8n.
2. В [@BotFather](https://t.me/BotFather) создайте тестового бота командой `/newbot`. Откройте личный чат с новым ботом, нажмите **Start** и отправьте ему сообщение. Из ответа метода `getUpdates` возьмите `result[].message.chat.id`. [Документация Telegram Bot API](https://core.telegram.org/bots/api#getupdates)
3. Импортируйте `avtomatizaciya/zayavka-telegram.json` через **Import from File**. В узле **Telegram** создайте credential **Telegram API**, вставьте токен бота в **Access Token** и заполните **Chat ID**. Токен хранится в n8n.
4. Опубликуйте workflow. Доска по умолчанию отправляет POST на `http://localhost:5678/webhook/zayavka`. Для другого экземпляра скопируйте `.env.example` в `.env.local`, задайте **Production URL** и перезапустите Vite. Если адрес доски или её порт отличается от указанных в workflow, добавьте его в **Allowed Origins (CORS)** узла Webhook.
5. Создайте заявку с комнаты **216Б** и отметьте «Срочно». Проверьте, что в сообщении бота есть комната, категория, «Статус: Новая» и срочность. В **Executions** проверьте успешное выполнение. Снимок реального уведомления сохраните в `screenshots`.
6. Выполните `docker compose stop` и отправьте ещё одну заявку. Она сохранится на доске, а отправка будет отмечена как неподтверждённая. После `docker compose start` отправьте новую заявку для контрольной проверки. Повторная отправка заявок, принятых при остановленном n8n, не выполняется.

Workflow состоит из Webhook, Telegram и Respond to Webhook. Последний узел возвращает `{"delivered":true}` после выполнения узла Telegram. Заголовок, комната и остальной текст заявки экранируются перед отправкой как HTML. [Webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/) · [Respond to Webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.respondtowebhook/) · [Telegram](https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.telegram/)

## Приёмочная проверка

В отдельном терминале запустите проверку типов и сборку, линтер и тесты формы, сохранения и отправки.

```bash
npm run build
npm run lint
npm test
```

1. На чистом хранилище сравните счётчик в шапке и счётчики фильтров с пятью карточками.
2. Отправьте пустую форму и проверьте два сообщения под кнопкой. Заполните название, оставив пробелы в комнате, затем проверьте обратный случай. Подсветка и сообщение должны относиться к пустому полю.
3. Введите название, комнату и подробности, смените категорию и отметьте «Срочно». После отправки проверьте очистку формы, первую позицию и выделенную рамку карточки.
4. Откройте и скройте подробности. Возьмите заявку в работу, верните в новые, снова возьмите в работу и завершите. Проверьте фильтры и счётчики после каждого изменения.
5. Найдите заявку по части названия другим регистром. Введите запрос без совпадений и проверьте пустое состояние.
6. Перезагрузите страницу и проверьте статус заявки. Уберите готовую заявку и убедитесь после обновления, что она удалена.
7. Проверьте успех отправки с подключённым workflow и сообщение об ошибке с недоступным вебхуком.

## Вопросы к защите

- **Зачем `key={request.id}`?** После вставки или удаления React узнаёт существующую карточку по ID и сохраняет её локальное состояние, например раскрытые подробности. При ключе-индексе это состояние может перейти на соседнюю заявку.
- **Зачем `preventDefault()`?** Обычная отправка HTML-формы запускает навигацию страницы. Вызов отменяет её, чтобы заявку обработал React.
- **Почему счётчики и видимый список вычисляются при рендере?** Их полностью определяют текущий массив, поиск и фильтр. Вычисление из этих данных поддерживает согласованность интерфейса.
- **Почему `useState(loadRequests)` без скобок?** React вызывает функцию как инициализатор состояния при монтировании. Вызов `loadRequests()` в аргументе повторял бы чтение при каждом рендере.
- **Почему сначала добавляем заявку?** Сохранение заявки в браузере работает независимо от сети. Результат уведомления показывается, когда вебхук ответит.
- **Где токен?** В Telegram credentials экземпляра n8n. Браузер знает только адрес вебхука.

## Вопросы по автоматизации

- **Почему токен хранится в n8n?** Файлы и запросы фронтенда видны через DevTools. Сервер n8n использует токен из Telegram credentials.
- **Чем отличаются Test URL и Production URL?** Test URL доступен во время прослушивания тестового события. Production URL принимает запросы после публикации.
- **Зачем Allowed Origins?** Этот параметр разрешает браузеру передать запрос из нужного origin доски в n8n. Origin включает схему, имя хоста и порт.
- **Зачем том в Compose?** `n8n_data` хранит базу, настройки и credentials при пересоздании контейнера. Данные вне тома теряются при удалении контейнера.
- **Что подставляет `$json.body.room`?** Значение поля комнаты из JSON новой заявки, например `216Б`.
- **Как добавить статус?** В тексте узла Telegram значение берётся из `$json.body.status`. При создании доска устанавливает статус «Новая».

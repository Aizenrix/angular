# Модуль 2 · Заявки в общежитие

Доска на React и TypeScript. PocketBase хранит заявки и передаёт изменения открытым вкладкам. n8n отправляет новые заявки локальной модели qwen2.5:3b и уведомляет мастера в Telegram.

## Что сделано

- В обязательной части есть коллекция PocketBase с пятью записями и правилами доступа, загрузка с повтором, хук `useRequests`, подписка и два сценария n8n.
- В дополнительных заданиях реализованы метка срочности от модели, имя мастера, время создания, поиск и переключение между подпиской и опросом каждые 10 секунд.

## Запуск

Нужны Docker Desktop и Node.js 20.19+ или 22.12+. Освободите порты 5173 и 5678, если на них запущен первый модуль. Его данные можно сохранить, остановив контейнер без удаления тома.

Из подкаталога `avtomatizaciya`:

```bash
docker compose up -d --build
docker compose exec ollama ollama pull qwen2.5:3b
docker compose ps
```

Миграция при первом запуске создаёт коллекцию `obshchezhitie` и добавляет пять заявок в трёх статусах. Панель PocketBase доступна на http://localhost:8090/_/. Суперпользователь нужен для панели и ручного исправления данных. Доска и сценарии используют публичные правила коллекции. [Миграции PocketBase](https://pocketbase.io/docs/js-migrations/) · [Правила API](https://pocketbase.io/docs/api-rules-and-filters/)

Из корня проекта:

```bash
npm ci
npm run dev
```

Откройте http://localhost:5173. Оба адреса API можно задать в `.env.local` по образцу `.env.example`.

## Два процесса n8n

На компьютере, где проводилась проверка, процессы уже опубликованы в Docker-проекте `doska-module2`. При чистом развёртывании выполните следующие шаги.

1. Создайте бота через BotFather и нажмите Start в личном чате с ним. Получите ID чата методом `getUpdates`. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates)
2. Из `avtomatizaciya/.env.example` создайте `avtomatizaciya/.env`. Заполните `TELEGRAM_TOKEN` и `TELEGRAM_CHAT_ID`, затем примените настройки командой `docker compose up -d n8n`. Файл остаётся на компьютере.
3. Откройте http://localhost:5678 и импортируйте `n8n/ii-dispetcher.json` и `n8n/knopka-vzyat.json`. В узлах Telegram выберите credential с токеном этого бота. В узле отправки «Telegram» укажите `={{ $env.TELEGRAM_CHAT_ID }}` в поле **Chat ID**. Поле пустое в выгрузке для сдачи.
4. Опубликуйте оба процесса. Путь первого процесса — `POST /webhook/zayavka`. Для одного бота должен работать один процесс, запрашивающий `getUpdates`. [Публикация вебхука](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook/)

Доска сначала сохраняет заявку в PocketBase. Диспетчеру передаётся ID. n8n читает запись, запрашивает ответ модели по JSON-схеме, сохраняет категорию и срочность и отправляет сообщение. Подтверждение в интерфейсе означает приём вебхука. Фактическое уведомление видно в Telegram. [Структурированные ответы Ollama](https://docs.ollama.com/capabilities/structured-outputs)

Процесс кнопки опрашивает Telegram каждые 10 секунд. Он принимает нажатия для этой доски из настроенного чата. PocketBase переводит только новую заявку в работу при назначении мастера. Затем n8n снимает кнопку с сообщения, обновляет статус и добавляет «Взял: имя». SSE обновляет открытую доску.

## Проверка

```bash
npm run build
npm run lint
npm test
npm run test:integration
npm run test:model
```

Интеграционные тесты требуют запущенного PocketBase, проверка модели — скачанной qwen2.5:3b в Ollama. Тесты правил создают свою заявку и удаляют её после проверки. Скрипт модели оценивает шесть примеров из общежития. Образцы выводов и снимки перечислены в `PROVERKA.md`.

1. Откройте две вкладки с режимом «По событиям». Добавьте заявку в первой. Во второй должна появиться одна карточка.
2. В Telegram проверьте категорию и нажмите «Взять». В обеих вкладках появляется статус «В работе» и имя мастера. Перезагрузите страницу и проверьте, что состояние сохранилось.
3. Остановите базу командой `docker compose stop pocketbase` и обновите доску. После `docker compose start pocketbase` нажмите «Повторить».
4. Сравните режимы «По событиям» и «Опрос каждые 10 с» по числу запросов списка за минуту в журнале PocketBase или вкладке Network.

## К защите

- **Что вернёт создание со статусом «Готово»?** HTTP 400, поскольку `createRule` требует «Новая».
- **Зачем отмена и проверка актуальности запроса?** При повторе, смене режима или размонтировании старый ответ не должен перезаписать новый список. Загрузка завершается и при успехе, и при ошибке.
- **Почему хук вызывается один раз?** У шапки и списка общие данные. Второй вызов завёл бы ещё одно состояние, загрузку и подписку.
- **Почему карточка не дублируется?** Ответ POST и событие SSE объединяются по ID. При конфликте сравнивается серверное поле `updated`.
- **Для чего JSON-схема?** Она ограничивает категорию четырьмя значениями и задаёт булеву срочность и строку резюме. Смысловую точность категории проверяют отдельно.
- **Почему опрос раз в 10 секунд?** Локальный n8n сам забирает события Telegram. Облачному Telegram для входящего вебхука потребовался бы доступный извне HTTPS-адрес.
- **Как исправить категорию?** Мастер меняет её в панели PocketBase. Другие вкладки увидят исправление через подписку.
